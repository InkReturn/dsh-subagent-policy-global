# 全局子智能体模型策略 · 交互逻辑设计（v3）

> 版本：`0.3.3`
> 目标：让用户在**当前会话里 1 步启用策略**，在**全局设置里集中配置策略、模型池与默认**，在**执行洞察里看到真实委派路由**；所有操作**不跳弹窗、不双池割裂、状态与反馈可感知**。

---

## 1. 信息架构（IA）

```
全局子智能体模型策略（插件面板）
├─ 顶部单行栏（.lezsp-topbar）
│   ├─ 左：标题「子智能体模型策略」 + 版本徽标 + GitHub 链接 + 作用域徽标
│   └─ 右：范围切换胶囊组（当前页高亮蓝底 #4c8dff）
│       ├─ 当前会话   → 只做「选启用哪份策略」
│       ├─ 全局设置   → 做「默认策略 + 策略库 + 模型池 + 并发限制」
│       └─ 执行洞察   → 看「真实子智能体创建记录」
```

**设计原则：**
1. **会话 vs 全局分权**：会话内只选启用，不编辑；全局配置只在全局设置。
2. **不叠弹窗**：策略编辑走**整页**；选模型/能力卡/规则模型选择全部**行内展开**。
3. **不双池割裂**：策略编辑里可直接勾选「未入池」的可用模型，保存策略时**原子并入全局模型池**。
4. **状态必须带出口**：快照落后 → 一键同步；未保存修改 → 吸底操作条；冲突/只读/需刷新 → 明确横幅说明原因。
5. **长列表不滚屏找按钮**：已选模型默认折叠成 chips；展开列表支持搜索 + 按 provider 分组 + 批量选；模型池未保存操作条吸底。

## 2. 核心状态与数据实体

| 实体 | 来源 | 说明 |
|------|------|------|
| `snap.management.strategies` | 全局库 `global.library` | 策略列表（`id / name / type: fixed/auto/inherit / models / fixedRoute / strategyText / version`） |
| `snap.management.pool` | 全局库 | **全局模型池**：允许被策略引用的模型集合（含 `purpose / note / effort`） |
| `snap.candidates` | 宿主实时授权 | 宿主当前授权的候选模型（含 `authorized / available / reasoning.efforts`） |
| `snap.management.active` | 当前会话 | **当前启用快照**（启用那一刻生成；保存启用策略时同步重建） |
| `snap.defaultSetting.snapshot` | 全局默认 | **新会话默认快照**（独立拷贝；只影响新会话，不改已启用会话） |
| `snap.management.limits` | 全局库 | 并发与递归限制（`maxDepth / maxActive`） |
| `snap.host` / `capacity` | 宿主能力 | 宿主递归深度上限、并发上限（`host.maxActiveKnown=false` 时禁止启用/保存限制） |
| `snap.runs` | 插件记录 | 执行洞察：真实子智能体创建（请求路由 / 实际路由 / 状态 / 证据） |

**UI 本地草稿：**
- `strategyDraft`：策略编辑草稿（`dirty / type / models: Set<routeKey> / fixedRoute / guideMode / guideRules / guideFallback / strategyText`）
- `poolDraft`：模型池勾选草稿（`keys / entries`）
- `limitDraft`：并发与递归限制草稿
- `modelDraft`：单个模型的能力卡草稿（`purpose / note / effort`）
- `ui.detail`：当前展开的详情（`{ kind: 'strategy' | 'model', id? / key? }`）
- `ui.choiceOpen`：策略编辑候选列表是否展开
- `ui.guidePicker`：当前展开的规则模型选择面板索引（`-1` 表示无）
- 各搜索词：`poolQuery / choiceQuery / guideQuery / recordQuery`

## 3. 页面与交互逻辑

### 3.1 当前会话（`page = 'session'`）

**目标：让用户 1 步完成「本会话用哪份策略」。**

```
┌──────────────────────────────────────────────────────────┐
│ 策略开关 [Switch] 已启用「默认策略」 · Agent 自选 · 11 个候选 │
└──────────────────────────────────────────────────────────┘
选择本会话使用的策略                  新增/编辑/删除、全局默认都在「全局设置」
┌───────────────┐ ┌───────────────┐
│ 默认策略 当前启用│ │ 重活专用       │
│ 新会话默认      │ │ 固定模型       │
│ Agent 自选     │ │ [pv] model ✕  │
│ [pv] model ✕  │ │      [启用]    │
│        [停用]  │ └───────────────┘
└───────────────┘
```

| 交互 | 行为 |
|------|------|
| 策略开关关闭 | `strategy.close` → 当前会话回到宿主默认（通常跟随父模型） |
| 策略开关重新打开 | 恢复最近一次启用的策略（`restoreActive`）；若引用失效/未入池/宿主容量未知 → 顶部横幅说明 |
| 卡片「启用」 | `strategy.enable { id }` → 生成当前会话启用快照；成功后在卡片上显示「当前启用」徽标 |
| 卡片「停用」 | `strategy.close` |
| 引用异常 | `需调整`（不在池）/ `待恢复`（当前不可用）徽标 + 原因提示；点启用时若不可用则提示恢复后再启用 |
| 宿主并发上限未知 | 顶部横幅：禁止启用，但只读查看/关闭仍可用 |

**此页不提供**：新增/编辑/删除/设默认，全部引导到「全局设置」。

### 3.2 全局设置（`page = 'strategies'`）

由 4 个连续区块组成，按业务顺序排列：**新会话默认策略 → 策略库 → 模型池 → 并发与递归限制**。

#### 3.2.1 新会话默认策略

```
┌──────────────────────────────────────────────────────────────┐
│ 新会话默认策略 [Switch] 已设置「默认策略」 · Agent 自选         │
│                              只影响新会话；已启用会话不受影响 │
└──────────────────────────────────────────────────────────────┘
⚠ 默认快照落后于「默认策略」当前版本。            [ 一键同步 ]
```

- **开关**：开启时按当前默认策略或最近设过的默认策略恢复；关闭时 `default.clear`。
- **一键同步**：`strategy.default { id: defaultValue.sourceId }` → 按策略当前版本重建默认快照。
- **只影响新会话**：不会静默修改已启用会话。

#### 3.2.2 策略库

```
策略库 2 份                                            [＋ 新增策略]
┌──────────────────────┐ ┌──────────────────────┐
│ 默认策略 当前启用      │ │ 重活专用              │
│ 新会话默认(来源未更新) │ │ 固定模型              │
│ Agent 自选           │ │ [pv] model1 [pv] m2  │
│ [pv] model1 ... +5   │ │                      │
│ [编辑] [设默认] [删除]│ │ [编辑] [设默认] [删除]│
└──────────────────────┘ └──────────────────────┘
```

| 按钮 | 行为 |
|------|------|
| 编辑 | 进入整页策略编辑器（见 3.3） |
| 设为全局默认 | `strategy.default { id }` → 生成新会话默认快照 |
| 删除 | `strategy.delete { id }`；若当前启用或为默认来源则禁用按钮并提示先关闭/先改默认 |
| 新增策略 | 打开空草稿整页编辑器 |

模型 chips 最多展示 6 个，超出折叠为 `+N`（悬停可见完整列表）。

#### 3.2.3 模型池

```
模型池 · 全局候选超集；思考强度在这里逐行设置      [全选] [清空] [刷新候选]
[搜索模型/provider…] [选中当前筛选]        共 90 个模型 · 11 个入池
iflytek-openai                                          5/6 入池
☑ DeepSeek V4.1 Flash   [默认(可能最低) ▾] [配置]
☑ GLM-5.3               [high ▾]          [配置]
☐ Spark-X2.6            [默认(可能最低) ▾] [配置]
...
┌────────────────────────────────────────────────────┐
│ 有未保存的池修改        [放弃] [保存模型池] （吸底） │
└────────────────────────────────────────────────────┘
```

| 交互 | 行为 |
|------|------|
| 勾选/取消勾选 | 只改本地草稿，不立即保存 |
| 搜索 | 按显示名、模型 id、provider 过滤 |
| 选中当前筛选 | 将当前搜索筛选出的可用模型全部加入草稿 |
| 全选 / 清空 | 批量勾选/清空草稿 |
| 刷新候选 | 重新校验宿主授权与可用性，不自动删除历史引用 |
| **思考强度下拉** | **即改即存**（`pool.note { provider, model, purpose, note, effort }`）；空值显示「默认（可能最低）」 |
| 配置 | 行内展开能力卡（用途、通用说明、思考强度），编辑后保存说明 |
| **吸底保存条** | 草稿与已保存不一致时浮在可视区底部，随时「放弃 / 保存模型池」 |
| 移除保护 | 若当前启用策略仍引用待移除模型，保存被拒绝并列出引用模型 |

#### 3.2.4 并发与递归限制

```
最大递归深度 [ 5 ]  并发子智能体 [ 5 ]  宿主上限：深度 3 · 并发 200    [保存限制]
```

- 未保存修改时显示「放弃」和「保存限制」。
- 宿主并发上限未知时禁止保存限制，并提示原因。
- 超出宿主上限时显示冲突横幅，但不自动修改已保存值。

### 3.3 策略编辑（整页）

```
← 返回全局设置
编辑策略 · 默认策略                                [当前启用]
当前会话启用中；保存后，在下一次主 Agent 发起模型调用时生效。

策略名称 [默认策略_______________]   路由方式 [Agent 自选 · 多选 | 固定模型 · 单选]

┌─ 候选子集 ────────────────────────────────────────┐
│ 候选子集 已选 11 个                    [展开候选列表]│

│ （展开后）                                         │
│ [搜索…] [选中当前筛选] [清空]                       │
│ iflytek-openai                             已选 5  │
│ ☑ DeepSeek V4.1 Flash        思考：max            │
│ ☐ Spark-X2.6 [未入池]          思考：默认          │
└────────────────────────────────────────────────────┘
带「未入池」的模型勾选后自动加入模型池，保存策略时原子提交。

选择说明 · Agent 自选时如何挑模型     [结构化规则 | 自由文本]
规则从上到下匹配，命中即停；规则内模型顺序 = 优先级。   [＋ 添加规则]
┌──────────────────────────────────────────────────────┐
│ 1. 当任务涉及 [开发 / 写代码 / 调试_______] ▲ ▼      ✕│
│ [1) DeepSeek V4.1 Flash ✕] [＋ 选模型]                │
│   （展开后）搜索… → 候选列表，选中项右侧「优先 1」徽标 │
└──────────────────────────────────────────────────────┘
兜底（无规则命中时）[复杂重构优先 kimi 系列________________]
注入预览（保存并注入子会话的就是这段文本）
┌──────────────────────────────────────────────────────┐
│ 【选择规则 v1】                                        │
│ 1. 开发 / 写代码 / 调试 → iflytek-openai/DeepSeek...  │
│ 兜底：...                                             │
└──────────────────────────────────────────────────────┘
                                          [取消] [保存策略]
```

#### 3.3.1 路由方式切换

- `Agent 自选`：多选候选子集，Agent 在子集内按说明挑模型。
- `固定模型`：单选；切换时若已有候选，只保留一个并设为固定路由。
- 切回 `Agent 自选` 时清空固定路由。

#### 3.3.2 候选子集

- **默认折叠**：只显示已选 chips，避免长列表占满屏幕。
- **展开**：显示搜索框 + `选中当前筛选` + `清空` + 按 provider 分组的完整候选列表。
- **未入池模型**：显示橙色「未入池」徽标，但仍可勾选。
- **保存时原子入池**：
  1. 检测 `strategyDraft.models` 中不在 `management.pool` 但 `candidates` 里 `authorized && available` 的模型；
  2. 先调用 `pool.save` 将这些模型并入全局池；
  3. 再调用 `strategy.save` 保存策略；
  4. 任一步失败都显示错误，不会静默成功。

#### 3.3.3 选择说明

**结构化规则：**
- 每条规则：`场景输入框` + 有序模型 chips + 上移/下移/删除。
- `＋ 选模型` 在规则内展开面板：搜索候选子集、勾选顺序即优先级，选中项显示「优先 N」。
- 兜底：无规则命中时的一句话说明。
- **注入预览**：实时显示最终编译出的 `strategyText`（`【选择规则 v1】...【/选择规则】`），重新打开时可解析回规则表单。

**自由文本：**
- 直接编辑 `strategyText`，用于兼容旧说明；切回结构化时原文保留为兜底。

#### 3.3.4 保存 / 取消

- **保存策略**：
  - 无修改 → 提示「没有需要保存的修改」；
  - 表单错误 → 顶部错误横幅 + 聚焦首个错误字段；
  - 当前启用策略 → 保存同时重建启用快照，下次模型调用生效；
  - 未启用策略 → 仅更新策略库；
  - 成功后返回全局设置列表，顶部显示「已保存「xxx」」。
- **取消**：有未保存修改时确认放弃；返回全局设置。

## 4. 状态机与反馈

| 状态 | 触发 | 界面表现 |
|------|------|----------|
| `loading` | 首次进入 / 刷新 | 顶部徽标「正在读取…」，按钮禁用 |
| `saving` | 任意写操作 | 顶部徽标「正在保存…」，显示「取消等待」 |
| `noSnapshot` | 读取失败 | 横幅提示 + 「重试读取」 |
| `readOnly` | 当前会话无编辑权限 | 顶部横幅，所有编辑控件禁用 |
| `mustRefresh` | 写操作被取消/结果未知 | 横幅：再次写入前需先刷新确认 +「刷新服务端状态」 |
| `conflict` | 服务端 revision 已更新 | 横幅：版本冲突，本地草稿保留 +「载入服务端版本」 |
| `noChanges` | 保存时无修改 | 提示「没有需要保存的修改」 |
| `saved` | 保存成功 | 返回列表 + 顶部成功提示 |
| `dirty pool` | 模型池草稿与已保存不一致 | 吸底操作条 |
| `stale default` | 默认快照版本落后于策略 | 橙色横条 +「一键同步」 |
| `needsAdjust` | 策略引用不在池 | 卡片徽标 + 启用前需调整 |
| `pendingRecovery` | 引用模型当前不可用 | 卡片徽标 + 恢复后可启用 |
| `host capacity unknown` | 宿主并发上限读取失败 | 禁止启用/保存限制；只读/关闭/池编辑仍可用 |

## 5. 关键用户流程

### 流程 A：新用户配置一份策略并启用
1. 打开「全局设置」→「新增策略」。
2. 输入名称，选「Agent 自选」。
3. 展开候选列表，搜索并勾选模型（可含未入池模型）。
4. 添加结构化规则（如：开发 → DeepSeek，润色 → Gemini）。
5. 查看注入预览，点「保存策略」（未入池模型自动并入池）。
6. 回到「当前会话」，点该策略「启用」。

### 流程 B：把某策略设为新会话默认
1. 「全局设置」→ 策略库 → 目标策略「设为全局默认」。
2. 若提示「来源未更新」，点「一键同步」。
3. 新会话自动导入该默认；已启用会话不受影响。

### 流程 C：调整模型思考强度
1. 「全局设置」→ 模型池。
2. 找到目标模型，直接改右侧「思考强度」下拉（即改即存）。
3. 需要补充用途时，点「配置」行内编辑并保存说明。

### 流程 D：在策略里引入一个新模型
1. 编辑策略 → 展开候选列表。
2. 搜索并勾选带「未入池」徽标的模型。
3. 点「保存策略」→ 自动先并入模型池，再保存策略。
4. 无需先回模型池手动勾选。

### 流程 E：查看子智能体实际用了哪个模型
1. 打开「执行洞察」。
2. 按 provider 筛选或搜索任务名。
3. 展开记录，对比「请求模型」与「实际模型」及证据。

## 6. 设计边界

- **不扩大授权**：所有可选模型都来自宿主当前授权；Agent 不能自行修改策略，必须由用户发起。
- **不静默删除历史引用**：模型不可用或不在池时保留引用并提示，不自动清除。
- **不自动修改已启用会话**：全局默认只影响新会话；当前启用快照只在本会话保存/启用时重建。
- **无弹窗**：所有配置均为整页或行内展开，避免层级迷失。
- **保存可见**：每次保存都有明确成功/失败/无变化反馈，禁止静默 return。
