## 二、共识

1. **总体方向正确**：三层 IA、不叠弹窗、整页编辑、长列表折叠与吸底保存条的方案可保留。
2. **“原子入池”当前并未真正实现**：只是前端 `pool.save` + `strategy.save` 两次顺序请求，且第一步绕过了互斥/取消/mustRefresh 治理。
3. **存在至少 3 个必须立即修的数据正确性问题**：
   - 池草稿保存会丢失全部已配置 `effort`；
   - 冲突时「载入服务端版本」会静默丢弃本地草稿；
   - 规则与子集脱钩会注入子集外模型，导致委派被拒。
4. **默认快照与启用快照、模型池之间不是完整同步**：改 effort/purpose/limits 不会让默认快照显示“落后”。
5. **90+ 模型时性能有实测瓶颈**：候选渲染 O(n²)、整库写放大、焦点被抢、串行写队列阻塞。
6. **测试不足以证明设计承诺**：写路径、冲突、原子入池、UI 交互大量依赖人工点检。

## 三、分歧与需要拍板

| 分歧点 | 两种选择 | 建议 |
|---|---|---|
| 原子入池实现方式 | A. 前端继续两次请求 + 补偿提示；B. 后端单 action 一次落盘 | **选 B**：`strategy.save` 支持 `poolAdditions`，一次 `mutate` 完成 |
| active 语义 | A. 保持全局 active，改文案；B. 改为真正 per-session active | **先改文案为“全局启用（所有会话共用）”**，长期再评估 per-session |
| 默认快照同步 | A. 写时回灌；B. 读取时实时派生 | **选 A（写时回灌）**，实现成本更低且能复用现有 stale 检测 |
| 思考强度保存语义 | A. 保持即改即存；B. 改为草稿+批量保存 | **保留即改即存，但服务端改增量**，避免整库写放大 |
| 宿主容量未知 | A. fail-closed；B. 未知按 32 并提示 | **改 B**：不阻断主功能，只给警告，因为宿主仍会执行自身上限 |
| UI 验收方式 | A. 人工验收清单；B. DOM 级自动化 | **先 A 后 B**：先建立可勾选的人工验收清单，再逐步补 reducer/纯函数测试 |

## 四、主会话建议（按优先级）

### P0 · 必须先修的数据正确性
1. **修池草稿 effort 丢失**：`draftsFrom`、批量勾选、`reset.model` 统一保留 `effort`；`savePool` 以已保存 entry 为底，只合并 keys 差异。
2. **修 loadServer 丢草稿**：载入服务端版本前复用 `discardIfDirty()` 确认，或提供“保留本地副本”。
3. **修规则与子集脱钩**：`choose(false)/clearChoice/switchType` 同步过滤 `guideRules[].models` 并重编译 `strategyText`；保存前校验规则引用 ⊆ 候选子集。
4. **原子入池下沉后端**：`strategy.save` 支持 `poolAdditions`，在同一 `mutate` 事务里并池 + 存策略 + 一次 revision；池满 200 时明确报错，禁止 `slice` 静默截断。
5. **active 语义改文案**：当前实现是全局 active，所有“本会话启用”改为“全局启用（所有会话共用）”或明确区分。

### P1 · 状态一致性与性能
6. **默认快照写时回灌**：`savePool/savePoolNote/saveLimits` 同步更新 `defaultSetting.snapshot` 的 `modelsInfo/limits` 并推进 revision；池删除增加默认快照引用保护。
7. **结构化错误码**：后端返回 `{code, message}`（如 `revision-conflict`），前端按 code 判 conflict，删除中文正则嗅探。
8. **渲染索引化**：一次性构造 `Map<key, info>`，替换 `choiceLabel` 里的 `JSON.parse + 线性 find`；`keyOf` 改非序列化拼接键。
9. **思考强度改增量**：服务端 `pool.note` 不重建全量 active 快照、不全量解析池；客户端只更新对应 entry，不整页禁用。
10. **消除冗余 commit 与焦点抢走**：删 `finally` 重复 commit；焦点 effect 只在页面/详情切换时触发；保存期间只禁用相关行。

### P2 · 测试与可维护性
11. **补写路径后端测试**：`strategy.save/delete/default`、`pool.save` 移除保护、`limits.save` 宿主未知、revision 冲突、原子入池成功/失败路径。
12. **把并池计算和 perform reducer 抽成纯函数**：在 VM/node:test 中直接测边界（200 上限、未授权、 unavailable、kept/reset 矩阵）。
13. **补人工验收清单**：折叠/搜索/批量选/吸底条/规则编辑/注入预览/默认同步/冲突保留草稿/未入池自动入池。
14. **拆分渲染组件**：按 session/strategies/records 拆子组件，使用 `React.memo` 与 `useDeferredValue`，避免全页随按键重建。
15. **服务端解析护栏**：`modelCatalog` 加缓存 + 并发上限 + 单路由超时；`assertEffortSupport` 并行化；`availabilityOf` 只校验新增项。

## 五、UX 主会话补评

- **信息架构合理**：会话选策略、全局做配置、洞察看证据，符合“使用”和“配置”分离。
- **主要认知负担在三个概念**：`模型池`、`启用快照`、`新会话默认快照`。建议：
  - 模型池改名为“全局候选池”，说明“只有池里的模型才能被策略直接引用”；
  - 当前启用改为“全局启用（所有会话共用）”，避免用户以为是当前会话私有；
  - 默认快照卡片明确写“仅新会话生效，已启用会话不变”。
- **未入池徽标太技术化**：建议改为“未加入全局池（保存策略时自动加入）”，并配一次性说明。
- **长列表体验方向正确**，但需保留滚动位置与输入焦点；保存期间不要整页变灰，只禁用相关行。
- **注入预览很有价值**，建议增加“复制文本”和“规则引用不在候选子集”红色提示。

---

## 六、盲区提醒

- 多模型意见一致不等于验证通过；本报告主要是静态代码评审 + 局部基准，**未在真实 DSH 面板里完成 90 模型实测**。
- `active` 全局化是否有意设计，需要与最初 fork 目标再对齐；若确实要 per-session active，则是更大的语义变更。
- `runs` 执行洞察记录无限增长，长期需要保留上限。
- 旧版“多候选固定策略”在编辑器里会被收敛成单模型，升级迁移说明需要补充。
- 默认快照采用写时回灌后，跨会话读放大和 revision 语义需要重新跑一遍后端测试。

---

**结论**：当前 v0.3.3 属于**有条件接受**。先修 P0 的数据正确性问题，再处理 P1 的状态一致性与性能，最后补 P2 的测试与组件化，才能达到设计文档承诺的体验。
